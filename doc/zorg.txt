INTRODUCTION                                                *zorg-introduction*

zorg.nvim provides the Neovim integration shell for Zorg `.z` files.

The plugin detects `.z` files, exposes a stable setup entry point, registers
command surfaces, wires the `zorg-ls` language server, and connects Neovim's
Tree-sitter runtime to the `zorg-treesitter` parser and query files. Zorg
semantics stay in the Rust CLI, language server, and Tree-sitter grammar.

==============================================================================
SETUP                                                            *zorg-setup*

Add the plugin with your preferred plugin manager, then call:
>
  require("zorg").setup()
<

Example with lazy.nvim:
>
  {
    "zettel-org/zorg-nvim",
    config = function()
      require("zorg").setup()
    end,
  }
<

Example with packer.nvim:
>
  use({
    "zettel-org/zorg-nvim",
    config = function()
      require("zorg").setup()
    end,
  })
<

Example with a sibling development checkout:
>
  vim.opt.runtimepath:prepend("~/projects/github/zettel-org/zorg-nvim")
  require("zorg").setup({
    cli = {
      command = "~/projects/github/zettel-org/zorg/target/debug/zorg",
    },
    lsp = {
      command = { "~/projects/github/zettel-org/zorg/target/debug/zorg-ls" },
    },
  })
<

Default options:
>
  require("zorg").setup({
    root = "~/zorg",
    database_path = nil,
    db_path = nil,
    trace = nil,
    log_level = nil,
    cli = {
      command = "zorg",
    },
    commands = {
      enabled = true,
    },
    watcher = {
      enabled = true,
      autostart = false,
      debounce_ms = nil,
      show_logs = false,
      job_policy = "per_root",
    },
    mappings = {
      enabled = false,
      prefix = "<leader>z",
      keys = {
        capture = "c",
        export_current = "e",
        fix = "f",
        index = "i",
        open = "o",
        query = "q",
        status = "s",
        watch_start = "w",
        watch_status = "S",
        watch_stop = "W",
      },
    },
    lsp = {
      enabled = true,
      autostart = true,
      command = { "zorg-ls" },
      root_markers = { ".zorgroot", "init.z" },
      database_path = nil,
      db_path = nil,
      refresh_on_save = "diagnostics",
      trace = nil,
      log_level = nil,
      settings = {},
    },
    treesitter = {
      enabled = true,
      parser_name = "zorg",
    },
  })
<

No global keymaps are installed.

COMMANDS                                                      *zorg-commands*

The plugin defines these user commands:

                                                        *:ZorgIndex*
:ZorgIndex [args]       Run `zorg db reindex --root {root}` with optional args.

                                                        *:ZorgStatus*
:ZorgStatus [args]      Run `zorg db status --root {root}` with optional args.

                                                        *:ZorgWatchStart*
:ZorgWatchStart [args]  Start one `zorg watch --format json` job for the
                        configured root.

                                                        *:ZorgWatchStop*
:ZorgWatchStop          Stop the managed watcher job for the configured root.

                                                        *:ZorgWatchStatus*
:ZorgWatchStatus        Open a lightweight watcher status buffer.

                                                        *:ZorgQuery*
:ZorgQuery [args]       Run `zorg query --root {root}` with optional args and
                        JSON result buffers by default.

                                                        *:ZorgFix*
:ZorgFix [args]         Run `zorg fix --root {root}` with optional args.

                                                        *:ZorgCapture*
:ZorgCapture [args]     Run `zorg capture --root {root}` with optional args.

                                                        *:ZorgPath*
:ZorgPath @id [args]    Open the source location returned by
                        `zorg path --format json`.

                                                        *:ZorgOpen*
:ZorgOpen @id [args]    Open the source location returned by
                        `zorg open --format json`.

                                                        *:ZorgPromote*
:ZorgPromote @id [args] Preview a `zorg promote` refactor, confirm, then
                        rerun with `--write`.

                                                        *:ZorgMove*
:ZorgMove @id --to target [args]
                        Preview a `zorg move` refactor, confirm, then rerun
                        with `--write`.

                                                        *:ZorgExtract*
:[range]ZorgExtract @new/id [args]
                        Convert the selected/current range to the Rust
                        extract contract, preview, confirm, then rerun with
                        `--write`.

                                                        *:ZorgImportPlan*
:ZorgImportPlan [args]  Run `zorg import legacy plan --json` and render a
                        review buffer.

                                                        *:ZorgImportApply*
:ZorgImportApply[!] [args]
                        Confirm, then run `zorg import legacy apply --json`.
                        The bang form skips confirmation.

                                                        *:ZorgExportMarkdown*
:ZorgExportMarkdown [args]
                        Run `zorg export markdown` with explicit selectors.

                                                        *:ZorgExportCurrent*
:ZorgExportCurrent [args]
                        Export the current buffer's canonical zettel ID with
                        `zorg export markdown --id`.

                                                        *:ZorgExportSubtree*
:ZorgExportSubtree @id [args]
                        Export a subtree with `zorg export markdown --subtree`.

                                                        *:ZorgExportQuery*
:ZorgExportQuery {query}
                        Export an inline query result set with
                        `zorg export markdown --query`.

If the `zorg` executable is unavailable, commands fail with a clear error and
make no changes.

Inline query text is passed as a single CLI argument, so:
>
  :ZorgQuery #z/todo -did:*
<
is sent as one SWOG query. Stored query zettel may be run with:
>
  :ZorgQuery --id @queries/today
<
`:ZorgQuery` prefers `zorg query --json` and renders LIST/TABLE buffers.
Use <CR> or `o` on a result row to open its source location. Pass
`--format list` or `--format text` for raw human output.

`:ZorgWatchStart` runs `zorg watch --root {root} [--db {db}] --format json`,
adds `--debounce {ms}` when `watcher.debounce_ms` is configured, and refuses to
start a duplicate job for the same resolved root. Watcher lifecycle JSON
states are surfaced through notifications and `:ZorgWatchStatus`. Watchers are
stopped on Neovim exit.

`:ZorgFix` defaults to the current `.z` buffer when no file argument is given.
If that buffer is modified, write it first or use `:ZorgFix!` to write before
running the fix command.

`:ZorgPath` and `:ZorgOpen` consume the Rust JSON location contract and jump to
the returned `absolute_path` plus source span. `:ZorgPromote`, `:ZorgMove`, and
`:ZorgExtract` force JSON previews, refuse direct `--write` invocation, and
only rerun with `--write` after an explicit confirmation. `:ZorgExtract`
converts the command range to `--file {current}` and
`--range START_LINE:START_COL-END_LINE:END_COL`; Lua does not edit source text.

Import review buffers group planned writes, warnings, lossy transforms,
unsupported forms, errors, and apply write results from the Rust JSON
contracts. Export commands display Markdown stdout directly and render JSON
directory/write reports when `--json` or `--format json` is requested.

==============================================================================
RUST CONTRACT NOTES                                  *zorg-rust-contracts*

Epic 15 features consume Rust-owned contracts only. Current stable Rust
surfaces for Neovim are:

- `zorg watch --root {root} [--db {db}] --format json`, which emits
  line-delimited lifecycle objects with `schema_version`, `state`, `root`, and
  `database`.
- `zorg query --root {root} [--db {db}] --json`, including inline queries and
  `--id @query/id`, with schema-versioned `list`, `table`, or `aggregate`
  envelopes.
- `zorg-ls` initialization options for `rootPath`, `databasePath`/`dbPath`,
  `trace`, `logLevel`, and `refreshOnSave`; graph freshness remains a
  Rust/LSP responsibility.
- `zorg path`/`zorg open`, `zorg promote`, `zorg move`, `zorg extract`,
  `zorg import legacy`, and `zorg export markdown` JSON/text contracts when the
  installed `zorg` binary provides those commands.

zorg.nvim wrappers for watcher lifecycle, JSON query buffers, refactors,
import, and export must shell out to those Rust contracts. If a user's local
`zorg` binary lacks a command, the wrapper should report the feature as
unavailable instead of parsing, rewriting, importing, or exporting Zorg data in
Lua.

OPTIONAL HELPERS                                          *zorg-helpers*

No global mappings are installed by default. To opt in to a small keymap set:
>
  require("zorg").setup({
    mappings = {
      enabled = true,
      prefix = "<leader>z",
    },
  })
<

The default opt-in key suffixes are `i` reindex, `q` query prompt, `o` open ID
prompt, `f` fix current buffer, `c` capture prompt, `s` database status, `w`
watch start, `S` watch status, `W` watch stop, and `e` export current zettel to
Markdown stdout. The mappings call thin Lua helpers that delegate to the same
command runner as the `:Zorg*` commands and do not parse Zorg data in Lua.

==============================================================================
LSP                                                                *zorg-lsp*

By default, `zorg.nvim` starts `zorg-ls` for buffers with filetype `zorg` when
the executable is available. Existing `zorg-ls` clients are reused when their
root matches the resolved buffer root.

Root detection first looks upward for configured root markers and otherwise
falls back to `~/zorg`, matching the Zorg v1 default root. The default markers
are `.zorgroot` and `init.z`.

The client sends Rust server configuration through LSP initialization options:
`rootPath` is the resolved root, `databasePath`/`dbPath` come from
`database_path`/`db_path`, `trace`/`logLevel` come from `trace`/`log_level`, and
`refreshOnSave` comes from `lsp.refresh_on_save`. These values may be
configured either at top level or under `lsp`, except `refresh_on_save`, which
is LSP-specific.

The default `lsp.refresh_on_save = "diagnostics"` keeps save handling on live
buffer diagnostics and avoids a corpus-wide `Store::reindex()` from the editor
save path. Use `lsp.refresh_on_save = "reindex"` to opt into save-driven index
refreshes, or `false` as an alias for diagnostics-only saves. For large
corpora, prefer `:ZorgWatchStart` or `watcher.autostart = true` so `zorg watch`
owns background index freshness. Set `lsp.autostart = false` to keep commands
and Tree-sitter without automatically starting `zorg-ls` for Zorg buffers.

Server behavior, diagnostics, completion, references, and rename safety belong
to `zorg-ls`.

==============================================================================
TREE-SITTER                                                *zorg-treesitter*

`zorg.nvim` registers filetype `zorg` to use parser language `zorg` and ships
Neovim query files copied from `zorg-treesitter/queries`.

The parser itself is expected to come from `zorg-treesitter` or a
plugin-manager parser installation. For sibling-repo development, build or
install the parser from `../zorg-treesitter`, then make the compiled
`parser/zorg.{so,dylib,dll}` file available on Neovim's 'runtimepath'. This
plugin does not implement Zorg syntax in Lua.

The parser language and Neovim filetype names are both `zorg`. During setup the
plugin registers that mapping with `vim.treesitter.language.register` when the
API is available.

==============================================================================
HEALTH                                                        *zorg-health*

Run:
>
  :checkhealth zorg
<

The health check reports whether the Lua modules load, the `zorg` and `zorg-ls`
executables are present with versions when available, watch/query JSON and
import/export contracts appear in the installed `zorg` help output, the
configured root and database path are clear, effective watcher settings are
visible, and the Tree-sitter runtime, parser, and query files are available in
Neovim. It also reports whether the Neovim version satisfies the 0.10+ support
target.

semantics. Those integrations delegate to the Zorg CLI, language server, and
Tree-sitter parser.
